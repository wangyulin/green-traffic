# 《GreenTraffic 城市交通碳排放实时监测与优化系统》实战课程大纲

## 课程概述

本课程以 **GreenTraffic 城市交通碳排放实时监测与优化系统** 为核心实战项目，采用"边讲边做、逐层迭代"的教学模式。学生将从零开始，逐步构建一个具备实时数据采集、存储、分析、可视化及优化建议功能的完整系统。课程结束时，学生将拥有一个可直接展示的 Portfolio 项目，并具备大厂实习面试所需的核心技术能力。

---

## 项目背景与功能全景

### 系统定位
面向城市交通管理部门的碳排放实时监测平台，通过接入路口摄像头、地磁传感器、车载 GPS 等数据源，实时计算路段碳排放量，提供拥堵预警、信号灯优化建议、减排报告等功能。

### 核心功能模块
| 模块 | 功能描述 |
|------|----------|
| 数据采集层 | 接收传感器上报的车流量、车速、车型数据（模拟器产生） |
| 实时计算层 | 基于排放因子模型计算 CO₂ 排放量，使用 InfluxDB 存储时序数据 |
| 监测展示层 | 实时大屏展示各路段碳排放热力图、趋势图、排行 |
| 优化建议层 | 基于规则引擎生成信号灯配时优化建议、拥堵预警 |
| 报告系统 | 定时生成日报/周报，支持历史数据查询与导出 |
| 系统管理 | 传感器管理、路段配置、用户管理、操作日志 |

- 消息模式：点对点、发布订阅、Topic、RPC
- 消息可靠性：持久化、确认机制（ACK）、死信队列
- Spring AMQP 的使用

**项目实战**：
- 系统架构升级：引入 RabbitMQ 作为数据接入层
  - 传感器数据先发送到 MQ（`sensor.data.queue`）
  - 数据消费服务从 MQ 消费数据，进行校验、计算、存储
  - 这样前端上报接口可以快速返回，实现削峰填谷
- 实现 `SensorDataProducer`：将上报数据发送到 MQ
- 实现 `SensorDataConsumer`：消费数据，调用计算服务，写入 MySQL + InfluxDB
- 配置消息确认机制（手动 ACK）、死信队列（处理无效数据）
- 模拟高并发场景测试（使用 JMeter 发送 1000 条/s）

**课后作业**：
- 对比 Kafka 和 RabbitMQ，什么场景选择哪个？
- 思考：如何保证消息不丢失？（生产者确认、消费者手动 ACK、持久化）

**项目实战**：

## 教学建议

1. **每节课安排**：前 40 分钟理论讲解 → 40 分钟项目实战 → 30 分钟答疑与代码 Review → 10 分钟总结与作业布置

2. **代码管理**：每节课结束后，将代码提交到对应的分支（如 lesson-01、lesson-02），方便学生回退查看

3. **迭代开发**：每节课在上一课的基础上迭代，学生能清晰看到系统的演进过程

4. **面试关联**：每节课的"课后思考"都关联面试高频题，帮助学生积累

5. **实战优先**：理论讲解尽量结合项目代码，避免"纯理论课"的枯燥感
