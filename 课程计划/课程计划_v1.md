# 一、课程总体定位

### 项目名称

**GreenTraffic 城市交通碳排放实时监测与优化系统**

> 面向城市交通管理部门，对道路车辆流量、平均速度、拥堵指数、能源消耗、碳排放等数据进行实时采集、计算、存储、监控和分析，并通过实时告警、趋势分析和交通优化建议辅助城市交通管理。

```text
│      ↓                                          │
│  Mapper                                         │
└──────────┬───────────┬───────────┬──────────────┘
           │           │           │
           ▼           ▼           ▼
        MySQL       InfluxDB       MQ
           │           │           │
           │           │           └── 实时数据/告警
           │           │
           │           └── 交通时序数据
           │
           └── 业务数据
           
              ↓
       定时任务 / 数据统计
              ↓
       碳排放分析 / 交通优化
              ↓
        WebSocket实时推送
```

# 二十一、最终课程的核心理念

我尤其建议把这门课定义成：

> **《从 Java 基础到企业级后端实战——GreenTraffic 城市交通碳排放实时监测与优化系统》**

而不是：

> 《Java 全栈技术培训》

因为学生真正需要形成的是下面这个能力闭环：

```text
学一个知识
     ↓
理解为什么需要它
     ↓
在 GreenTraffic 中使用
     ↓
遇到 Bug
     ↓
Debug
     ↓
理解底层原理
     ↓
总结面试问题
     ↓
继续扩展项目
```

最终学生能够把自己的项目讲成：

> “我负责了 GreenTraffic 城市交通碳排放实时监测系统的后端开发，系统采用 Spring Boot + MyBatis + MySQL 构建业务服务，使用 InfluxDB 存储交通时序数据，通过 RabbitMQ 解耦实时数据处理和告警业务，通过 WebSocket 实现交通状态实时推送，同时使用 AOP 实现接口日志，通过全局异常处理和统一响应规范 API，通过定时任务完成周期性数据计算，并针对 MySQL 查询进行了索引优化……”

**这句话本身就是一段非常好的实习项目介绍。**

而课程最终要达到的，不是学生“学过 Java、Spring、MySQL、MQ”，而是让学生能够**拿着自己的 GreenTraffic 项目，把上面每一个技术点打开代码、讲清原理、解释为什么这么设计、回答面试官追问，并现场修改代码**。

如果按这个目标继续往下设计，我下一步会把它进一步细化成一套真正可以拿去授课的 **40 次课教学大纲**：每次课明确到 **“第几分钟讲什么、PPT 讲什么、代码写什么、项目新增什么功能、课后作业是什么、面试题是什么、教师演示代码和学生实操作业分别是什么”**，并把 GreenTraffic 的**数据库表结构、后端包结构、模块拆分、API 清单和每阶段项目版本**一起定下来。
