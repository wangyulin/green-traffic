# 二十、但是不要过度抽象

这里我要提醒你一个坑。

千万不要一开始设计：


然后搞一个：


最后所有数据库都强行塞进一个接口。


所以：

> **抽象“业务需要的能力”，不要抽象“数据库所有能力”。**

比如业务真正需要：


就抽象这些。

不要试图抽象：

```text

SQL
TSDB native query
Retention Policy
Bucket
Measurement
Super Table
Tag
```

这些属于 Adapter 内部。

```text
      │     model    │
      │     core     │
      │      api     │
      └──────────────┘
             │
             │
      只有 Adapter 不同
             │
      ┌──────┴──────┐
      ↓             ↓
   Cloud          Private
  InfluxDB        TDengine
  RocketMQ        RabbitMQ
```

这对你以后做**交通数字孪生平台、智慧交通平台产品化**其实非常重要。

# 三十、我建议下一步不要急着写 Repository

我们现在已经把**架构方向**确定了。

下一步最值得做的是直接把这个架构**落到你现在这套 green-traffic 的 Maven POM 上**，也就是：

```text
① 根 pom.xml
       ↓
② common
       ↓
③ model
       ↓
④ core
       ↓
⑤ infrastructure
       ↓
   ├── infra-mysql
   ├── infra-influxdb
   ├── infra-tdengine
   ├── infra-iotdb
   ├── infra-rocketmq
   └── infra-rabbitmq
       ↓
⑥ api
⑦ push
⑧ simulator
```

然后我建议我们**以 InfluxDB 为第一个完整 Adapter**，真正把它从 POM 一直到代码跑通：

```text
application.yml
       ↓
InfluxDBProperties
       ↓
InfluxDBConfig
       ↓
InfluxDBClient
       ↓
InfluxDBTemplate
       ↓
TrafficTimeSeriesRepository
       ↓
InfluxTrafficTimeSeriesRepository
       ↓
TrafficService
       ↓
TrafficController
       ↓
POST /traffic
       ↓
InfluxDB
```

与此同时，把 **TDengine / IoTDB / RocketMQ / RabbitMQ 的 Port 留好**，但先不实现，这样不会一开始把项目搞得过度复杂。

**我尤其建议下一步先把 `green-traffic-model` 和 `green-traffic-core` 两个模块重新设计清楚。** 因为这两个模块一旦定下来，后面的 InfluxDB、TDengine、IoTDB、MySQL、RocketMQ、RabbitMQ 都只是“插拔式实现”，否则后面很容易反复返工。
